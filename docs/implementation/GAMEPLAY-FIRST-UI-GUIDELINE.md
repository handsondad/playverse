# 游戏页统一设计规范

本规范用于后续所有小游戏页面，默认采用“主玩法优先”的产品布局。

## 核心原则

1. 第一眼先看到怎么玩，不先看到设置和统计。
2. 主路径永远最短：选难度/主题 -> 点开始 -> 立即进入游戏。
3. 选择项尽量用大按钮，不优先使用下拉框。
4. 主操作贴近游戏区域，避免用户视线来回跳。
5. 设置、统计、排行榜属于辅助信息，统一放在页面底部弱化展示。

## 推荐页面结构

1. 顶部标题区
   标题、简短玩法说明、休息提示、返回入口。
2. 选择区
   难度、主题、模式等，优先用横向大按钮。
   如果同一区域同时存在“选择项”和“开始/重试/每日”按钮，必须继续拆成两个视觉分组。
3. 主玩法区
   开始游戏、预览、核心道具、实时状态、主游戏画面。
4. 辅助区
   每日挑战、语音、护眼模式、数据统计、排行榜。

## 控件规范

1. 难度/主题使用按钮组，当前选中必须有明显高亮。
2. 开始游戏按钮是最强视觉按钮。
3. 当开始游戏、重试、每日挑战仍放在选择区时，必须单独加“开始操作”标题。
4. `selector-actions` 必须采用独立卡片背景、边框或留白，不得与 `level-buttons` 混成同一视觉层。
5. 选择按钮和开始操作按钮不能使用同一套基础底色，至少要在色相或明度上明显区分。
6. 核心道具按钮与开始游戏放在同一区域。
7. 设置按钮尺寸可稍小，但仍需满足触屏点击。

## 分区规范

1. `level-buttons` / `theme-buttons` / `mode-buttons` 负责“先选什么”。
2. `selector-actions` 负责“开始做什么”。
3. 两组之间至少满足以下 3 条中的 2 条：
   加独立标题。
   加容器背景或边框。
   按钮配色体系不同。
4. 用户在不阅读文案的情况下，也应一眼分辨“这是选择项”还是“这是开始操作”。
5. 若页面已有主题选择，再加入开始操作时，顺序固定为：难度/模式 -> 主题 -> 开始操作 -> 说明文案。

## 视觉层级

1. 主玩法区颜色更亮、边界更清晰、占位更大。
2. 底部辅助区透明度更低、阴影更轻、信息密度更高。
3. 状态栏靠近游戏区域，方便边玩边看。
4. 选择区内的开始操作组，要比难度按钮更醒目，但不能压过主玩法区。

## 交互规范

1. 点击后要有即时高亮反馈。
2. 主题和难度切换后，页面要立刻反馈当前选择。
3. 动态引导文案优先放在标题说明区，不额外打断游戏区。
4. 同一页面中，选择按钮的激活态和开始按钮的按下态不能表达混淆。

## 默认适配策略

1. 桌面端：选择区和主玩法区优先横向布局。
2. 移动端：按钮组可改为单列，但顺序不变，且开始操作卡片仍独立保留。
3. 任何新游戏都先保证“能玩、易懂、少跳转”，再逐步补统计和扩展功能。

## 落地检查清单

1. 是否一眼能看出“难度/主题按钮”和“开始/重试/每日按钮”不是一类控件。
2. 是否存在 `level-btn` 与 `selector-actions button` 复用同一基础底色的情况。
3. 是否在选择区加入了 `action-title` 或同等层级标题。
4. 是否在移动端宽度下仍能保持选择区和开始操作区分层。
5. 新游戏合入前，至少做一次这份清单的人工走查。
